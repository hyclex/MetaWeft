# Base v1 design

This variant implements the MetaWeft blueprint as a ReMe-inspired system comparison. Its parent is the bundled `metaskill-appworld/baselines/reme2f37a15` AppWorld implementation, not the different shared ReMe pilot adapter. Compared with that parent, it adds explicit task-conditioned adaptation, permits evidence-grounded learning from failures, and uses semantic add/skip/revise/defer consolidation without utility eviction. The matched direct setting disables all memory stages.

The base owns the flat memory fields, one embedding of `when_to_use + "\n\n" + content`, cosine retrieval (`k=5`, `num_candidates=10`), one adaptation pass, and sequential post-task policy. Elasticsearch and LLM services contain no research policy. HNSW indexing is explicit and vectors remain in source snapshots. Memory starts empty for each independent run/split and persists in task order within that stream.

`BasePipeline.prepare_context(task_spec, llm=..., artifacts=...)` returns fixed execution guidance and recorded status. Empty memory skips embedding/adaptation. A non-provider retrieval or adaptation failure produces visible degraded status and empty guidance. Exhausted provider failures propagate and stop the stream. `post_task(evidence, llm=..., artifacts=...)` reflects zero to three candidates, then consolidates each against the store including earlier confirmed updates. Task completion, official evaluation and execution remain the benchmark adapter's responsibility.

Evidence files contain only whitelisted task-specification fields, step/code/observation traces, and scalar reward. Relative source references resolve within the preserved run. Consolidation receives full deduplicated source evidence; missing or invalid source evidence defers the candidate without overwriting memory. Evaluator reports, assertions and solutions are never prompt inputs. Revised records retain their original references plus all evidence consulted for the revision, since the model can use supporting evidence from multiple neighbors. Deferred decisions remain in update logs.

Storage failures and invalid nonempty structured model output are recorded as degraded stages; JSON is not repaired. Confirmed candidate writes remain, later candidates are not processed, and uncertain writes remain explicitly uncertain. `LLMUnavailableError` bypasses stage fallback. The worker preserves failure evidence and recovers from the preceding committed task, excluding incomplete-task updates. Artifact, required checkpoint export, and canonical model-log failures are fatal. There is no deletion, eviction, graph, hybrid retrieval, query decomposition, iterative adaptation, within-task resume, parallel stream mutation or configurable workflow engine. Future variants must propagate provider exhaustion and use the shared experiment checkpoint contract.

Prompts live under `prompts/v1`. The separate `execution_base.txt` and `execution_direct.txt` initially contain the identical parent `NEW_PROMPT_TEMPLATE` from `benchmark/appworld/prompt.py`; the adapter controls whether adapted guidance is appended. They are independent experimental variables for later revisions. Run snapshots retain the actual prompt text and copied-source provenance.

The first two-task live base run exposed a consolidation prompt issue: some add responses echoed candidate text into fields that the strict schema requires to be null. Task one made no write; task two retained one confirmed write before a later candidate failed. Both tasks were recorded as degraded. The consolidation prompt now gives separate examples for each operation and explicitly requires null unused fields. The schema, failure handling, and no-repair policy are unchanged. A fresh two-task run completed without degradation and exercised retrieval, adaptation, addition, revision, and redundancy skipping; see [validation evidence](../../experiment/appworld/VALIDATION.md). The original run remains preserved.
